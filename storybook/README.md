# Careers sites Storybook

Design system of the careers sites (Blue Shield of California, Stellarus, Ascendiun slot): guides, design
tokens per brand, every block and variation, and page templates, all rendered with the site's own code.

## Commands

```bash
cd storybook
npm install
npm run storybook        # dev server on http://localhost:6006
npm run build-storybook  # static site in storybook-static/ (host at the root of a domain)
npm run fixtures         # refresh content fixtures and generated stories from ../content
```

The toolbar **Brand** switches the theme (Page default, Blue Shield, Stellarus, Ascendiun); it can be set
in the address with `&globals=brand:stellarus`.

## How it works

- `.storybook/main.js` serves the site folders (`blocks`, `scripts`, `styles`, `fonts`, `icons`,
  `favicons`) at their site paths, plus `public/`. The site needs no build step and has no
  Storybook-specific code.
- Every story renders `public/sb-frame.html` in an iframe (`src/frame.js`). The frame loads a content
  fixture (`public/fixtures/<path>.plain.html`), moves its Metadata block into `<head>` like the server
  does, applies the selected brand as `theme` metadata, turns the cookie banner off, and imports
  `/scripts/scripts.js`: the page is decorated exactly as on the site. The iframe grows to its content.
- `public/sb-tokens.js` draws the Foundations token tables from `/styles/brand.css`, with the values
  resolved for the selected brand.
- Mock data at site paths: `/nav.plain.html`, `/footer.plain.html`, `/blog/query-index.json`,
  `/sitemap.json`, `/blog/external-stories.json`, `/tools/library/blocks.json` (one file per sheet:
  `blocks.options.json`, mapped by the frame's fetch shim).

## Files

| Path | Kind |
| --- | --- |
| `stories/guides/*.mdx`, `stories/foundations/*.stories.js` | Hand-written |
| `public/fixtures/foundations/*` | Hand-written fixtures (typography, buttons, section styles, empty page) |
| `stories/blocks/*`, `stories/templates/*` | Generated by `npm run fixtures`: one story per library example (named after its Library Metadata `name`), docs text from `blocks/<block>/README.md` |
| `public/fixtures/blocks|templates|pages`, `public/*.plain.html`, `public/blog`, `public/tools`, `public/media-da`, `public/drafts` | Generated by `npm run fixtures` from the local content export |

`npm run fixtures` reads `../content` (the local `.plain.html` export used by the local preview); it is not
committed, so run it on a machine that has the content export, then commit the regenerated files.

## Notes

- Photos load from their original addresses (internet connection needed).
- Blue Shield fonts come from the Adobe Fonts kit; if the kit does not allow the Storybook's domain, the
  metric-matched fallbacks are shown.
- The Storybook is kept out of the site: `storybook/*` is in `.hlxignore`, its packages and build output
  in `.gitignore`, and it has its own lint scope (root `.eslintignore`).
